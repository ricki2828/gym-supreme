# Contract changes

- 2026-11-23: Pigeon v1, `WorkoutApi` + `WorkoutEvents` (live session, export share, native counters). Lane A.
- 2026-11-23: `HostInfo` gains `release`, `notificationsEnabled`, `batterySaver`; `GymHostApi.openNotificationSettings()` (Diagnostics, plan 6.2 banner). Additive. Native lane, with its Kotlin implementation.
- 2026-11-23: `GymHostApi.takeLaunchCommand()` (CI e2e; the `gym_e2e` launch extra, once; dogfood/debug only, null on play). Additive. Native lane.
- Planned v1.1 (additive, cut 2): service-to-Dart action events for lock-screen Done / +1 rep / Skip rest (WorkoutActionReceiver); Kotlin applies Done and Dart resyncs from the rev. Binary export (zip) would need a bytes variant of shareFile.
- 2026-11-23: session_snapshot schema 1, pre-merge (PR #7, t5z; t5v acked each round): added set keys `plan_load_g`, `plan_reps` (after `kind`); added top-level `set_ready_at_ms`, `next_set_n`, `swaps` (after `ended_at_ms`); strict decode on both sides; encoding pins (U+2028/2029/DEL raw, lone surrogates, no doubles); cut-2 `block` keys (t61). Nothing had shipped, so `schema` stays 1. Lane t5z.
- 2026-11-23: `block.run` added (additive, cut 2; t61 + t5v); Kotlin dedup key becomes (set_id, run, index). Session.undo keeps `run`. Lane t5z (PR #17).
- 2026-11-23: refusal code `io_error` (real I/O failure, e.g. deleteJournal), native counter `journal_delete_failed` (#19). Additive. Lane A doc, native lane code.
- 2026-11-23: `GymHostApi.requestNotificationPermission()` (@async bool; POST_NOTIFICATIONS on API 33+, notificationsEnabled below; refusal code `already_pending`). Additive. Native lane.
- 2026-11-24: v1.1 lock-screen actions (0.3 cut L1, flag `lockdone`). No Pigeon change, no schema change. Kotlin applies Done / +1 rep / Skip rest itself (`core/session/LockReducer.kt`, byte-for-byte twins of `Session.done(source: lockscreen)`, `Session.retarget(reps: +1)`, `Session.skipRest`), journals the result as rev + 1 and emits it on `WorkoutEvents.snapshots`; `LiveController` adopts a same-workout snapshot at a higher rev. Guard: shared vectors `lockscreen_v1_*.json`, generated from the Dart transitions. No Done / +1 on timed sets, blocks, null reps, or a loaded lift with no target weight. Native lane.
- 2026-11-24: `GymHostApi.pickImportFile()` (@async String?; I1 import). ACTION_OPEN_DOCUMENT, no permission; returns the file text (strict UTF-8) or null on cancel / activity gone; refusal codes `already_pending`, `too_large` (over 16 MiB), `io_error`. Logcat `import_pick_shown`, `import_pick` (result picked|cancelled|too_large|io_error|no_picker|activity_gone). Additive. Lane E/U (I1).
- 2026-11-24: export `export_format` 2 gains an optional per-workout `hr` list of `[t_ms, bpm]` (left out when empty; additive). Import (I1) reads format 1 and 2, refuses newer format / schema / snapshot schema. Lane E/U (I1).
- 2026-11-24: `pickImportFile` cap lowered from 16 MiB to 8 MiB (peak heap; the codec re-encode runs on the main thread). A year at 4 sessions a week, 24 sets each, exports about 2.3 MiB without HR. Doc only on the Dart side.
- 2026-11-24: correction to the entry above: the export does NOT carry `hr` (a 1 Hz strap would outgrow the 8 MiB pick cap within months). Import still reads an optional per-workout `hr` list when a file has one.
- 2026-11-24: export `export_format` 2 gains an optional top-level `starting_weights` list of `{exercise_id, load_g}` (0.3 S1; additive, no format bump: 0.2.x imports ignore the key, so a 0.2.2 import of a 0.3 file drops starting weights and keeps everything else). Import adds lifts that have none locally, never overwrites. No Pigeon change, no schema change (setting row). Lane E/U (S1).
- 2026-11-24: native timer cue scheduler (0.3 cut T1, flag `timers`). No Pigeon change, no schema change. Kotlin runs a pending set's started `block` (`core/timer/BlockScheduler.kt`): anchor once per (set_id, run, started_at_wall_ms), cue k at anchor + at_ms; fired (set_id, run, index) and (flag on only) fired rests, keyed by set_id + `ends_at_wall_ms` so a redone set's rest buzzes again, are committed to `files/journal/fired.txt` before the buzz (survives pause, process death, reboot; cleared with the journal; older runs dropped). Cues overdue by more than 5 s when the block is armed are logged `missed`, not played. Flag off: logged `timer_ignored`, nothing arms, no `fired.txt`; rests dedupe in memory as before. With the flag on, `getNativeCounters` gains `timer_cues_fired`, `timer_cues_late`, `timer_cues_missed`, `timer_cue_max_late_ms`, `timer_cues_audio_failed` and the last block's cue log (`timer_last_block_cues|fired|late|missed|max_late_ms`, `timer_last_cue_NN_late_ms`), so the Diagnostics export carries it; flag off, none of these keys appear. Guard: shared vector `timer_v1_emom20.json`, generated from TimerSession. Native lane.
- 2026-11-24: `HealthApi` (new host API, additive; 0.3 H1, flag `health`): `status()`, `setEnabled(bool)` (on asks for `WRITE_EXERCISE` on Health Connect's screen, refusal `already_pending`), `writeSessions(List<HealthSession>)` (upsert by `clientRecordId` = workout uuid, `version` = `edited_at_ms ?? 0`, batches of 100), `deleteSessions(List<String>)`; enums `HealthAvailability`, `HealthOutcome`, `HealthExerciseKind`; classes `HealthStatus`, `HealthSession` (with `kind`), `HealthResult`. Health Connect problems come back as an outcome, never an exception. One `ExerciseSessionRecord` (strength training; the Engine type is HIIT so conditioning never counts as strength; title = workout type, start/end with the workout's own offset); no sets, HR or pause segments. Logcat `health_status`, `health_permission_shown`, `health_permission`, `health_write`, `health_delete`. The switch is Kotlin-side (app prefs, not in Auto Backup), off by default. Manifest: dogfood flavour + `health` flag only. With the flag on, the Diagnostics export gains `health_written`, `health_deleted`, `health_failed`. Native lane + E/U.
- 2026-11-24: H1 footprint, all builds: `androidx.health.connect:connect-client:1.1.0` + coroutines add about 357 KiB to the R8 dogfood APK (x64 21,714,636 vs 21,348,654 bytes at main 0af872f), flag on or off. The library merges an exported bind service (`androidx.health.platform.client.impl.sdkservice.HealthDataSdkService`, `enabled=true exported=true`, action `ACTION_BIND_SDK_SERVICE`) into every build: the main manifest removes it (`tools:node="remove"`) and `src/health/AndroidManifest.xml` declares it again, byte for byte (`tools:node="replace"`), only for dogfood builds with `health`. `tools/check_manifest_permissions.sh` fails if it appears with the flag off or is missing with it on, and prints its attributes (`tools/manifest_health_report.py`).
